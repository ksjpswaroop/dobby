## 用户

Add feature: Interactive Mind Mapping for Brainstorming with full CRUD.

Context:
This is a local-first AI idea-generation / business-planning application. The Brainstorming stage already supports generating, reviewing, and editing ideas. Add an interactive visual mind-map workspace that lets users turn brainstormed ideas into structured, editable concept maps.

Goal:
During brainstorming, users should be able to create, view, organize, edit, and persist a mind map alongside the existing brainstorm content. The map must support both AI-generated structures and manual editing.

Core requirements:

1. Brainstorming → Mind Map integration
- Add a “Mind Map” tab or toggle within the Brainstorming stage.
- When AI brainstorming produces categories, ideas, risks, opportunities, features, personas, or next steps, provide an “Generate Mind Map” action.
- The generated map should use:
  - Central node: project or idea title
  - First-level nodes: primary themes/categories
  - Child nodes: individual brainstorm ideas, assumptions, risks, opportunities, features, research questions, or action items
- Preserve links between the text brainstorm items and their corresponding map nodes where possible.

2. Full mind-map CRUD
Implement complete CRUD for maps and nodes.

Mind map:
- Create a new blank map
- Generate a map from brainstorming results
- Rename a map
- Duplicate a map
- Delete a map with confirmation
- Persist maps per project and per brainstorming session

Nodes:
- Create root, child, or sibling nodes
- Edit node title, description, type, color, and optional priority/status
- Delete a node and its descendants only after confirmation
- Move/re-parent a node using drag-and-drop
- Reorder sibling nodes
- Collapse/expand branches
- Duplicate a node with descendants
- Add/remove links between nodes when appropriate
- Support keyboard shortcuts where practical:
  - Enter: add sibling
  - Tab: add child
  - Delete/Backspace: delete selected node after confirmation
  - Escape: cancel edit

3. Node types
Provide a small consistent taxonomy:
- Idea
- Problem
- Opportunity
- Feature
- Risk
- Assumption
- Research Question
- Action Item
- Decision

Each type should have a readable visual treatment, but do not rely on color alone. Include icon/label support for accessibility.

4. UI/UX
- Use a clean canvas-based or graph-based interface with pan, zoom, fit-to-screen, minimap, and selection controls.
- Make the central concept visually distinct.
- Include a side panel / inspector for selected-node editing.
- Add toolbar controls:
  - Add Node
  - Generate with AI
  - Auto Layout
  - Undo / Redo
  - Expand All / Collapse All
  - Export
- Provide empty states for a new map and a map with no nodes.
- Keep the existing brainstorming text view intact; mind mapping is an enhancement, not a replacement.

5. AI assistance
- “Generate Mind Map” should take the current brainstorming content and return a structured JSON tree/graph, validated before rendering.
- Add “Expand selected node with AI” to generate 3–8 relevant child ideas.
- Add “Improve / regroup map with AI” as a preview-first operation:
  - Show proposed changes
  - Let the user accept/reject before modifying the saved map
- Never overwrite user edits silently.

6. Data model
Create a durable schema suitable for SQLite/local persistence.

Suggested entities:
- mind_maps:
  - id, project_id, brainstorm_session_id, title, root_node_id, viewport_state, created_at, updated_at
- mind_map_nodes:
  - id, mind_map_id, parent_id, title, description, node_type, color, position_x, position_y, sort_order, metadata_json, created_at, updated_at
- mind_map_edges:
  - id, mind_map_id, source_node_id, target_node_id, relation_type, created_at
- mind_map_history or operation log:
  - id, mind_map_id, operation_type, payload_json, created_at

Use migration(s), foreign keys, indexes, and safe cascading behavior. Do not delete brainstorm content when a mind map is deleted.

7. Reliability and safeguards
- Validate tree/graph integrity:
  - No orphan nodes
  - No invalid parent IDs
  - No self-referential or cyclic parent relationships
  - Root node rules enforced
- Support undo/redo for local edits.
- Autosave changes with visible save state.
- Prevent accidental deletion using confirmation dialogs.
- Ensure AI-generated output is schema-validated and gracefully falls back to a user-visible error if invalid.

8. Export/import
- Export mind maps as:
  - JSON for round-trip import
  - Markdown outline
  - PNG or SVG image, if supported by the selected visualization library
- Include map structure in project exports where applicable.
- Import valid JSON maps with validation and user-friendly errors.

9. Testing
Add tests for:
- Mind map creation, read, update, duplication, and deletion
- Node CRUD and hierarchy operations
- Drag/re-parent validation
- Cycle prevention
- Cascade-delete behavior
- Persistence and reload
- AI JSON schema validation
- Undo/redo
- Export/import round-trip
- UI empty/loading/error states

10. Implementation quality
- Reuse the application’s existing architecture, state management, UI components, and persistence conventions.
- Prefer a mature graph/mind-map library already compatible with the frontend stack, rather than building graph interaction from scratch.
- Keep the feature modular: separate domain model, persistence/repository layer, AI transformation service, state store, UI canvas, node editor, and tests.
- Do not introduce mock-only wiring. All visible CRUD actions must be fully wired to persistence.

Deliverables:
- Database migration(s)
- Backend commands/API handlers
- Frontend Mind Map workspace and node inspector
- AI map-generation and expansion workflow
- Export/import support
- Tests and documentation
- Update the Brainstorming stage so users can access and use the feature end-to-end

Acceptance criteria:
A user can create a project, brainstorm ideas, generate a mind map, manually add/edit/rearrange/delete nodes, save/reload the map, expand a node with AI, undo edits, export the map, and return later with all map data preserved.

### Issues found in the draft

**1. Data model misalignment with existing conventions**
The existing schema uses `extra_metadata = Column("metadata", JSON, default=dict)` — the suggested `metadata_json` should be `metadata` (column name) / `extra_metadata` (attribute name) to match convention. Same for `position_x`/`position_y` — existing code doesn't use spatial columns, so these are new, but they belong in `metadata` JSON rather than dedicated columns unless querying by position is needed.

**2. Missing `project_id` on nodes**
`mind_map_nodes` links to `mind_map_id` but not to `project_id`. The existing `Node` table has direct `project_id`. For query simplicity (e.g., "get all mind map nodes for a project"), a denormalized `project_id` on nodes is worth the redundancy.

**3. Undo/redo is underspecified**
"Support undo/redo for local edits" — should this use an operation-log replay or state-snapshot stack? For a mind map, a snapshot-based approach (serialize map → push to stack) is simpler and costs less to implement than operation-log CRDT. The draft mentions both `mind_map_history` and undo/redo but doesn't connect them.

**4. Library choice is a research gap**
React 18 + Tailwind + no existing canvas/ graph dependency. The draft says "prefer a mature graph/mind-map library" but doesn't name candidates. For React mind-mapping:
- **React Flow** (12.5k stars) — node-based, extensible, good for this use case, but more of a general graph editor
- **Markmap** — renders Markdown as mind maps, read-only focused
- **Simple Mind Map** (mind-elixir) — lightweight, but less maintained
- **Custom SVG/Canvas with d3-hierarchy** — more control, more work

**Recommendation**: React Flow (now `@xyflow/react` v12) is the strongest fit — it handles pan/zoom/drag/minimap out of the box, has React 18 support, and works with Tailwind.

**5. Missing scope boundary: "Brainstorming stage" integration**
The draft references "Brainstorming stage" as if it exists as a pipeline step. Need to verify: is this a wizard step? A session type? Integration depends on how brainstorming is modeled in the current system.

**6. Test list is ambitious but missing integration-test scope**
The draft lists unit-level tests but doesn't address: "AI generation → JSON validation → render" as an integration test. Given LLM output is nondeterministic, schema validation tests are critical and should be called out explicitly.

**7. Export formats — SVG/PNG dependency**
"PNG or SVG image, if supported by the selected visualization library" — React Flow supports `toSvg`/`toPng` via `@xyflow/react` utilities. This is a resolved question if React Flow is chosen.

---

4. **Phase split**: This is a large feature. Do you want the requirement to define phases (e.g., Phase 1: CRUD + canvas, Phase 2: AI integration, Phase 3: Export/import)?
